# PRD: 온라인 서점 상품 목록

## 1. 문서 목적

아우라웍스 풀스택 개발자 과제의 요구사항과 범위를 구현 전에 합의하고, 개발 및 검수 기준으로 사용한다.

- 과제 안내: Figma 신입사원 테스트 페이지
- 제출 기한: 2026년 10월 14일(수) 오후 5시
- 제출 방식: GitHub 공개 저장소와 배포 URL을 담당자에게 전달
- 기준 화면: 제공된 Figma 캡처와 과제 안내 원문. 화면의 세부 문구·수치가 이 문서와 다르면 Figma/안내 원문을 우선한다.
- 문서 상태: 2026-10-13 구현 결과 반영. Figma 확인 결과는 [figma-notes.md](figma-notes.md), 결정과 진행 상황은 [implementation-plan.md](implementation-plan.md)를 본다.

## 2. 과제 및 채용공고 분석

### 과제에서 확인되는 필수 항목

1. Next.js로 상품 목록 페이지를 구현한다.
2. Figma 화면을 기준으로 UI를 구현하고 화면 크기에 대응한다.
3. Supabase에 교재 더미 데이터를 저장한다.
4. 브라우저에서 상품 데이터를 조회(CSR)해 표시한다.
5. GitHub 저장소를 공개하고 Vercel에 배포한다.
6. 확장 가능한 프로젝트 구조와 설계 의도를 설명한다.

> 과제의 정확한 표현과 제출 조건은 Figma 원문을 최종 기준으로 한다. 원문은 "화면에 보이는 부분 위주로 작업할것"이라고 하므로, Figma에 보이는 검색·카테고리 탭·페이지네이션은 구현하고 화면에 없는 가격 정렬은 제외했다.

### 채용공고에서 읽히는 평가 관점

아우라웍스의 풀스택 공고는 Next.js 웹 개발, 반응형 UI/UX, FastAPI 백엔드, LangChain 기반 RAG 에이전트, AI 개발 도구 활용을 주요 업무로 제시한다. 자격·우대 항목에는 JavaScript, Git, Figma 협업, AI 관심, React Query, Supabase, 테스트 자동화, AX 개발이 언급된다.

이번 과제에서는 모든 공고 기술을 억지로 넣지 않는다. Next.js, Figma 재현, Supabase 데이터 연동, React Query 기반 상태 관리(선택), 명료한 코드 구조, 검증 및 README 설명으로 관련 역량을 보여준다. FastAPI·RAG·인증·결제는 과제 요구가 아니므로 구현하지 않는다.

## 3. 목표와 성공 기준

### 목표

Figma에 제시된 온라인 서점의 교재 목록 화면을 구현한다. 교재 정보가 Supabase에서 실제로 조회되며, 사용자는 목록을 탐색하고 교재명 검색과 카테고리(전체·패스·단품) 필터, 페이지 이동을 할 수 있다.

### 성공 기준

- 배포 URL에서 페이지가 정상적으로 열린다.
- 상품 데이터의 원천이 Supabase이며, 브라우저에서 조회 요청이 발생한다.
- 초기 로딩, 데이터 없음, 조회 오류 상태가 구분되어 표시된다.
- 핵심 화면이 모바일과 데스크톱에서 읽고 조작할 수 있다.
- GitHub 저장소에 실행 방법, 환경변수, 데이터 준비 방법, 주요 설계 결정을 설명한다.
- 배포 환경에 비밀키가 노출되지 않고 공개 읽기 정책이 의도한 범위에 한정된다.

## 4. 사용자와 핵심 흐름

### 사용자

교재 목록을 살펴보고 관심 있는 교재를 찾으려는 방문자.

### 핵심 흐름

1. 사용자가 목록 페이지에 진입한다.
2. 상품 영역은 로딩 상태를 보여주고 클라이언트에서 Supabase 데이터를 조회한다.
3. 조회가 끝나면 교재 카드 목록을 보여준다.
4. 사용자는 검색어를 입력하거나 카테고리 탭을 바꿔 목록을 좁혀 보고, 페이지를 이동한다.
5. 결과가 없으면 빈 상태를 확인하고 검색어를 수정한다.

## 6. 화면 요구사항

Figma 원본을 열어 실제 문구, 색상, 치수, 에셋을 확인하고 구현 시 보완한다. 제공된 화면을 기준으로 다음 영역을 포함한다.

1. **헤더/내비게이션**: 브랜드 영역과 메뉴, 사용자/장바구니 등 화면에 표시된 아이콘. 별도 동작이 요구되지 않으면 장식 또는 안내 링크로 처리한다.
2. **프로모션 영역**: 배너 이미지, 제목/설명, CTA. 제공된 에셋을 우선 사용하고, CTA 목적지가 정의되지 않았다면 임의 구매 흐름을 만들지 않는다.
3. **상품 목록 헤더**: 검색 입력과 카테고리 탭. Figma에 페이지 제목 텍스트는 없다.
4. **상품 카드**: 상품 이미지, 카테고리, 상품명, 가격. 할인 상품은 원가 취소선, 할인율, 판매가를 표시한다. 배지는 없다.
5. **목록 하단**: Figma의 페이지네이션(`<` `1` `2` `3` `>`)을 구현한다.
6. **푸터**: 원본 화면에 보이는 경우 범위에 포함한다.

### 반응형 기준

- 모바일 우선으로 구현한다.
- 작은 화면에서 가로 스크롤이나 카드 잘림 없이 검색, 카테고리 선택, 상품 탐색이 가능해야 한다.
- Figma에는 1440px 데스크톱 프레임만 있어 breakpoint를 직접 정했다: 768px 미만 2열, 768px(`md`) 이상 3열, 1280px(`xl`) 이상 4열. 768px 미만에서는 헤더 메뉴를 숨긴다. 기준은 README에 남긴다.

## 7. 상품 데이터 요구사항

### 데이터 필드 (확정)

| 필드           | 형식        | 규칙                                                  |
| -------------- | ----------- | ----------------------------------------------------- |
| id             | uuid        | 기본 키                                               |
| title          | text        | 필수, 교재명                                          |
| category       | text        | 필수, `pass` 또는 `single`. 화면 표기(패스·단품)는 코드에서 매핑 |
| image_url      | text        | 필수, `public/` 기준 경로(예: `/products/single.png`) |
| price          | integer     | 필수, 0 이상 원 단위 판매가                           |
| original_price | integer     | 선택, 0 이상. 할인 상품의 원가                        |
| discount_rate  | integer     | 선택, 0~100                                           |
| created_at     | timestamptz | 생성 시각, 기본 정렬 기준                             |

Figma 카드에 쓰이지 않는 `description`은 넣지 않았다. Figma의 76,000원·5%·64,800원은 계산상 맞지 않으므로 할인가를 계산하지 않고 `original_price`, `discount_rate`, `price`를 각각 저장해 그대로 표시한다. 카테고리는 DB에 영문 코드로 저장하고 한글 표기는 화면에서 바꾼다.

이미지는 과제 범위상 `public/`에 두고 DB에는 경로만 저장한다. 운영 시에는 Supabase Storage에 올리고 `image_url`에 Storage 경로를 저장한다.

### 데이터 및 보안

- 브라우저에는 Supabase URL과 공개 anon/publishable key만 사용한다.
- service role key, DB 비밀번호 등 서버 비밀값은 클라이언트 번들이나 공개 저장소에 넣지 않는다.
- 공개 목록 조회가 필요하면 상품 테이블의 SELECT만 허용하는 제한된 RLS 정책을 사용한다.
- 쓰기 권한은 공개 사용자에게 부여하지 않는다.
- 상품 이미지 URL은 배포 환경에서 실제로 로드되는지 확인한다.
- 스키마와 RLS는 `supabase/migrations/`의 마이그레이션 파일로 관리하고 Supabase CLI(`db push`)로 적용한다. SQL Editor에서 직접 실행하지 않는다.

## 8. 기능 상세와 수용 기준

### 상품 목록 조회 (필수)

- 페이지 진입 후 브라우저에서 Supabase 조회가 수행된다.
- 성공 시 조회된 각 레코드를 상품 카드로 표시한다.
- 조회 전 로딩 UI가 보인다.
- 레코드가 0개이면 빈 상태 안내가 보인다.
- 네트워크/DB 오류이면 오류 안내와 재시도 방법이 보인다.
- 데이터 배열이 비어 있거나 필드가 예상과 달라도 페이지 전체가 깨지지 않도록 기본값 또는 명확한 오류 처리를 둔다.

### 검색 (추가)

- 상품명 기준으로 검색한다.
- 검색어 앞뒤 공백을 정리한다.
- 결과가 없으면 빈 결과 안내를 보여준다.
- 검색 기준과 입력 UI가 명확하며, 검색어를 지울 수 있다.
- 데이터가 36건이므로 전체를 한 번 조회한 뒤 클라이언트에서 필터한다. 이유와 한계는 README에 적는다.

### 카테고리 필터 (추가)

- `전체 | 패스 | 단품` 탭을 제공하고 선택된 탭을 표시한다.
- 검색어와 카테고리를 함께 적용한다.
- 기본 순서는 `created_at`, `id` 오름차순이며 필터 후에도 이 순서를 유지한다.
- 가격 정렬은 Figma에 없어 제외한다.

### 페이지 이동 (추가)

- 페이지당 12개를 표시한다.
- 페이지 이동 후 목록과 현재 페이지 표시가 일치한다.
- 검색어나 카테고리가 바뀌면 1페이지로 돌아간다.
- 페이지가 1개뿐이면 페이지네이션을 숨긴다.

## 9. 비기능 요구사항

- TypeScript를 사용해 상품 데이터와 컴포넌트 입력을 표현한다.
- 데이터 접근 로직, 상품 UI, 공통 레이아웃을 구분하되 과제 규모에 맞게 과도한 추상화는 피한다.
- 반응형 이미지 크기와 비율을 안정적으로 유지한다.
- 키보드와 스크린 리더 사용자를 위한 입력 라벨, 버튼 이름, 이미지 alt를 제공한다.
- 콘솔 오류 없이 핵심 흐름이 동작해야 한다.
- 공개 URL에서 새로고침해도 페이지가 정상적으로 표시된다.

## 10. 기술 선택 가이드

과제에서 지정한 라이브러리는 없다. 채택한 구성은 다음과 같다.

- Next.js 16 App Router + React 19 + TypeScript
- Tailwind CSS v4
- Supabase JS client: `getSupabase()`로 지연 생성하고 브라우저에서만 호출
- TanStack Query v5: 조회의 로딩·오류·재시도(1회)·캐시만 담당. 별도 상태 라이브러리는 쓰지 않는다
- Vitest: 검색·카테고리 필터 순수 함수 단위 테스트
- 패키지 매니저 pnpm, Supabase CLI(`pnpm dlx supabase`)
- Vercel 배포, GitHub Actions(CI, Supabase keepalive)

## 11. 폴더 구조

기능 단위로 관련 코드를 모은다. 과제 규모에 맞게 하위 폴더(`components/`, `hooks/`)는 나누지 않았다. 전체 구조는 README를 본다.

```text
src/
  app/                 # layout, page, providers(QueryClient), globals.css
  components/          # Header, Banner, Footer (공통 레이아웃)
  features/products/   # types, api, utils(+test), ProductList, ProductToolbar, ProductCard, Pagination
  lib/supabase.ts      # Supabase 클라이언트
supabase/
  migrations/          # 스키마·RLS 마이그레이션
  seed.sql             # 더미 교재 36건
docs/                  # PRD, Figma 확인 결과, 구현 계획
```

## 15. 확인 결과 (구 미확인 사항)
